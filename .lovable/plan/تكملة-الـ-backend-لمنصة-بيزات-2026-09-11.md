# تكملة الـ Backend لمنصة بيزات

الهدف: تنفيذ نفس المطلوب (تسجيل المستخدم، استبيان المخاطر، إنشاء المحفظة تلقائياً، جلب المحفظة) على قاعدة بيانات المشروع الحالية التي تعمل فعلياً مع الموقع.

## ملاحظة على التقنية
لا يمكن تشغيل خادم Express أو الاتصال بـ MongoDB Atlas داخل هذه البيئة. المشروع الحالي يستخدم React مع طبقة خادم آمنة وقاعدة بيانات PostgreSQL مُدارة، وكل الوظائف المطلوبة قابلة للتنفيذ عليها بنفس النتيجة: بيانات حقيقية محفوظة، لا بيانات وهمية.

## الوضع الحالي (تم التحقق منه)
موجود بالفعل ويعمل:
- جدول المستخدمين (`profiles`) وجدول الاستبيان (`risk_assessments`) وجداول المحافظ النموذجية ومحفظة المستخدم والأصول.
- حساب درجة المخاطرة والمحفظة الموصى بها وحفظها عند إنهاء الاستبيان.
- صفحة النتيجة وصفحة المحفظة تقرأان من قاعدة البيانات مباشرة.

الناقص مقارنة بالطلب:
1. لا يوجد حقل رقم الهاتف ولا اسم كامل يُحفظ عند التسجيل.
2. لا يُنشأ ملف المستخدم تلقائياً عند إنشاء الحساب — يُنشأ لاحقاً وبشكل غير مضمون.
3. المحفظة لا تُنشأ تلقائياً بعد الاستبيان؛ تحتاج ضغطة زر إضافية.
4. لا توجد دالة موحّدة لجلب «محفظة المستخدم مع توزيع أصوله» بشكل مباشر.

## ما سيتم تنفيذه

### 1. قاعدة البيانات
- إضافة `phone` إلى جدول `profiles` (اختياري) مع بقاء الاسم والبريد وتاريخ التسجيل.
- إضافة مُشغّل (trigger) ينشئ صف `profiles` تلقائياً عند إنشاء أي حساب جديد، ويأخذ الاسم ورقم الهاتف من بيانات التسجيل.

### 2. دوال الخادم (بديل الـ API Routes)
- `registerUser` — إنشاء الحساب مع الاسم والبريد ورقم الهاتف وحفظ الملف الشخصي (يقابل `POST /api/user/register`).
- `submitAssessment` — يُوسَّع ليقوم بعد حساب الدرجة بإنشاء محفظة المستخدم وأصولها تلقائياً بناءً على المحفظة الموصى بها (يقابل `POST /api/survey/submit`).
- `getMyPortfolio` — يبقى كما هو مع توحيد شكل الاستجابة: نوع المحفظة، التوزيع الحالي، الرصيد (يقابل `GET /api/user/:id/portfolio`).
- معالجة أخطاء واضحة في كل دالة برسائل عربية مفهومة، والاستجابة دائماً بصيغة بيانات منظمة.

### 3. الواجهة الأمامية
- صفحة التسجيل: إضافة حقلي الاسم الكامل ورقم الهاتف وإرسالهما مع الحساب.
- صفحة الاستبيان: بعد الإرسال يذهب المستخدم مباشرة إلى النتيجة والمحفظة تكون جاهزة بلا خطوة إضافية.
- صفحة النتيجة: زر «افتح محفظتك» يفتح لوحة التحكم مباشرة على بيانات المحفظة المحفوظة.

## خارج النطاق
- لا Express ولا MongoDB ولا نشر على Vercel.
- لا تغيير في منطق حساب المخاطرة أو إعادة التوازن أو الأسعار الحية.

## ملاحظة أمنية
المفتاح الذي أرسلته ظهر في المحادثة؛ يُفضّل إلغاؤه لاحقاً من لوحة MongoDB. لن يُستخدم في المشروع.

## تشغيل واختبار
بعد التنفيذ: إنشاء حساب جديد بالاسم والهاتف، إكمال الاستبيان، ثم فتح لوحة التحكم للتأكد من ظهور المحفظة وتوزيع الأصول والرصيد من قاعدة البيانات.
